# 轻序 · 技术与使用说明（0.4.4）

轻序，让你听到真正想听的。

Android 8.0+ 原生通知收件箱，使用 Kotlin、Jetpack Compose、Material 3、Room 和 WorkManager。通知入库时即产生本机初步分类，后台按授权补充云端复核；显示保护与上传授权分别控制。当前是可安装的开发版，不提供分类准确率承诺。

- 当前公开源码；可按下文自行构建。安装包与本地工具链不提交至 Git。
- 界面预览见[项目首页](../README.md)，图片为虚构数据的 Compose 测试渲染，不是真机截图。
- 本次验证：见 [验证记录](VERIFICATION-0.4.4.md)。

## 使用流程

设置首页只呈现「整理哪些应用」与「隐私保护」两个主要入口。来源列表、搜索与通知授权在独立子页中；API、模型和测试连接放在低频的「高级设置」。未启用云端也会按本机规则自动整理，不要求先配置服务。

1. 先为手机设置系统锁屏密码。轻序默认保护通知内容，点击「解锁查看」并完成系统凭据验证后再查看消息、选择来源或修改受保护设置。没有设备锁时需先到系统设置中设置，不能直接跳过验证关闭保护。
2. 在「设置 → 整理哪些应用」中选择需要收纳的应用，并授予 Android 通知使用权。显示保护开启时，开启来源需要有效的解锁会话；停止某来源不要求再次验证。
3. 新通知入库时先在本机整理，首页按「现在看」「稍后看」「其他消息」显示；明确的营销可进入「已收起」。普通聊天无需手动归类；云端等待、失败或锁屏暂停时继续保留本机结果。
4. 解锁后卡片优先展示消息。点击「本机整理／云端分析」查看原因；点击「···」把单条消息设为优先查看、稍后查看或收起，也可展开完整正文。星标与查看原消息直接可用。
5. 「这类以后少显示」单独保存当前应用与内容类型的收起规则，可在「高级设置 → 关注与偏好」撤销。收起某购物应用的营销，不会因此收起它的交易消息。
6. 如需云端分析，在「设置 → 高级设置」选择接口类型，填写地址、实际模型 ID 与密钥。可先测试当前填写的配置，再勾选允许的来源、主动开启并保存。测试不会保存配置或改变云端授权；隐私页中的仅本机来源与锁屏限制仍优先生效。不启用云端也能使用本机规则、收纳与纠正。

新手指引放在真实控件旁：选来源 → 通知访问授权 → 查看离线自动整理示例 → 纠正一条 → 在「已收起」恢复。示例不会进入通知数据库或发送到云端，支持跳过、续学和重新体验。

## 显示保护与本机隐私

默认隐藏通知卡片的应用名称、标题、正文与判断理由；内容保护启用时，高级设置与隐私配置也先显示验证页。系统凭据验证成功后的查看会话最长 **120 秒**，应用进入后台或设备熄屏时立即锁回；会话只存在内存中。关闭显示保护也需要先验证。主界面使用 Android `FLAG_SECURE` 限制截图与最近任务预览，实际系统行为仍需真机验证。

「隐私保护」提供独立控制，云端选项在「云端隐私」中展开：

- **锁屏时不上传**默认开启。锁屏或熄屏时不发起新的云端通知分析，等待合适时机继续；已发出的请求无法撤回。
- **仅本机来源**优先于云端勾选。微信、QQ 与常见短信应用的包名默认加入仅本机集合；不保证覆盖所有通信应用、分身或厂商变体，需检查自己的来源列表。取消仅本机限制不会自动授予云端权限。
- **本机历史保留期**可选 7 天、30 天或不自动清理，默认不自动清理，避免升级后意外删除已有历史。保留期以本机记录最近更新时间为准，更改并保存后会清理已过期记录，后台也会执行清理。
- **删除全部本机历史**有二次确认，只删除轻序保存的通知与对应整理结果，不删除来源应用消息或系统通知，也不更改来源选择与隐私设置。已删除通知不会仅因监听重新连接就重新导入。

仅本机模式目前使用规则整理，**端侧 AI 模型尚未接入**。选用 Jev 或其他云端模型不等于本地运行，也不等于已授权上传。

## 自动整理如何工作

```text
来源应用发布通知
  → Android 通知监听
  → 同一事务内保存内容、版本和本机初步结果（敏感文本字段加密）
      → 明确急事：现在看
      → 普通消息、物流和非临近日程：稍后看
      → 正文不足：其他消息；明确营销：已收起
  → WorkManager 应用偏好，并复核本机规则未确定的消息
      → 常见敏感凭据：只在本机处理
      → 检查云端开关、来源授权、仅本机限制与锁屏状态
          → 允许：基础脱敏后调用所选服务
          → 不允许、锁屏暂停或分析失败：保留本机结果
  → 更新轻序列表，解锁后显示内容与判断原因
```

本机规则覆盖有限场景：可信购物来源的明确营销、交易或履约异常、普通物流与交易进度、明确临近日程、安全异常及常见验证码。普通聊天默认放到「稍后看」，近期且明确请求立即回复或处理的消息可放到「现在看」；聊天中的营销或交易词不会使它被自动收起。重新同步的旧日程不会仅因正文写着「10 分钟后」就列为当前紧急。这些是规则结果，不是端侧模型，也不覆盖所有应用与表达。

「其他消息」对应内部 `REVIEW` 分区，用于正文被隐藏、信息不足或不能安全确定的内容，并不要求用户逐条手动整理。普通消息的本机兜底结果保持可见；启用云端后，仅规则未确定且允许上传的消息才继续复核。升级时会重新整理选中来源中尚未解决的旧 `REVIEW` 结果，保留人工纠正和已完成的云端判断。

客户端校验服务返回的内容类型、重要性、紧急性、行动要求与置信信号，再决定分区。低置信、信息不足或未知类型保留在「其他消息」；只有满足更严格条件的营销结果才能收起。通知正文是待分析数据，不提供工具执行或系统操作能力。置信信号不代表已测量的准确率。

关注内容可用逗号分隔。本机按至少两个字符的词匹配，云端将其作为相关性背景；命中关注或已星标的通知从自动收起结果保留到「稍后看」。用户明确保存的应用／类型规则优先于关注匹配，单条人工纠正优先于自动结果。

单条纠正绑定当前内容版本。同一个系统通知 key 更新正文时，旧机器结果会被新的本机初分替换，随后按当前授权复核；星标保留。同正文快照不重置机器结果或人工纠正。恢复自动收起的内容会把当前消息固定为可见；手动收起再恢复则回到此前分区。

## 配置云端分析

在「设置 → 高级设置」验证身份后，按服务商文档选择接口类型。类型由协议决定，不由模型的显示名称决定；例如，名为 Claude 的模型也可能由中转服务通过 Chat Completions 提供。

| 接口类型 | 标准请求路径 | 鉴权 |
| --- | --- | --- |
| Chat Completions | `/v1/chat/completions` | `Authorization: Bearer` |
| Claude Messages（Anthropic Messages） | `/v1/messages` | 默认 `x-api-key`，也可按中转服务要求选择 `Authorization: Bearer`；均带 `anthropic-version: 2023-06-01` |
| Jev | 官方 `https://api.typesafe.ai/v1/systemone` | `Authorization: Bearer` |

Chat Completions 与 Claude Messages 支持两种地址模式。新安装默认使用「基础 URL」，界面会展示实际请求地址供核对；升级前已保存的地址保留「完整 URL」含义，不会被自动重新拼接。

| 地址模式与输入示例 | Chat Completions 实际请求地址 | Claude Messages 实际请求地址 |
| --- | --- | --- |
| 基础 URL：`https://api.example.com` | `https://api.example.com/v1/chat/completions` | `https://api.example.com/v1/messages` |
| 基础 URL：`https://api.example.com/v1/` | `https://api.example.com/v1/chat/completions` | `https://api.example.com/v1/messages` |
| 基础 URL：`https://api.example.com/gateway` | `https://api.example.com/gateway/v1/chat/completions` | `https://api.example.com/gateway/v1/messages` |
| 完整 URL：服务商指定的完整请求地址 | 去除首尾空白后原样使用，不补路径 | 去除首尾空白后原样使用，不补路径 |

上述 `api.example.com` 仅为示例域名。基础地址已经以对应协议路径结尾时不会重复追加；非标准网关路径应选择「完整 URL」。地址必须使用 HTTPS，不允许 URL 内嵌账号、密钥、查询参数、锚点、相对路径或路径转义字符；明确与所选协议冲突的路径会被拒绝。当前未支持 OpenAI Responses API，不能把 `/responses` 当作 Chat Completions 使用。需要查询参数的网关也不在本版地址支持范围内。

「模型名称」填写服务商 API 实际接受的 **模型 ID**，不要填写界面昵称、套餐名或自行缩写。以服务商文档或模型列表为准；Jev 可填 `jev-latest`。Jev 仅允许官方端点，**仍是云端请求**。没有真实服务账号的端到端验证结论；适配器和单元测试不能证明服务兼容性或中文分类质量。

Claude Messages 默认用 API Key 鉴权；中转文档若要求 Bearer Token，再选择该方式。每次只发送所选的一种凭据头，不同时试发两种。切换接口类型、主机、端口或 Claude 鉴权方式后，需要重新填写对应密钥，不能沿用其他服务的已存密钥。切换接口类型保留已有地址和模型，不扩大上传授权；首次选择 Jev 时会为留空字段填入官方地址与模型。请核对实际请求地址。

### 测试当前填写的配置

「测试连接」直接使用当前草稿，无需先保存；新填写的密钥只用于本次测试，不写入偏好存储。留空时仅在接口类型、主机、端口及 Claude 鉴权方式与已存配置一致时使用已存密钥。测试不保存草稿、不启用云端，也不改变已选来源与关注内容。

测试会向当前地址发送一次真实的 HTTPS POST，使用固定虚构物流通知、不包含真实通知或用户关注内容，可能消耗服务额度。只有请求成功且响应能够通过对应协议与通知分类结构校验，才显示成功；收到 HTTP 响应或网址可达并不算通过。这不验证模型对该样例的分类准确性。拒答、截断、工具调用或不合规分类会使测试失败。

测试仍遵守身份验证与锁屏限制。编辑连接草稿、修改相关设置、查看会话失效或锁屏时，旧测试会取消或失效；已经发出的请求无法撤回。网络错误、HTTP 400、401、403、404、429 与响应格式错误分别提示，不直接展示服务原始错误正文、请求内容或密钥。正式分析和测试均拒绝重定向。

| 提示 | 优先检查 |
| --- | --- |
| HTTP 400 | 接口类型、模型 ID 是否被该服务支持 |
| HTTP 401 | 密钥与鉴权方式是否正确 |
| HTTP 403 | 账号权限、地域或服务限制 |
| HTTP 404 | 实际请求路径及模型 ID |
| HTTP 429 | 额度与限流，稍后重试 |
| 无法解析域名、连接超时、HTTPS 验证失败 | 手机网络、代理、服务地址、设备时间 |

完成测试后，再按需保存配置与授权。测试通过不会替用户完成这一步。

云端分析默认关闭，新来源默认不允许发送。明确开启并保存后，允许范围内已收纳和后续收到的、需要云端判断的消息都可能提交。请求会包含应用名称、标题、正文、时间与关注内容。提交前会遮蔽常见电话、邮箱、长数字及链接，常见验证码等敏感凭据会阻止本次上传；**这只是基础脱敏，不是匿名化，也不能保证识别全部敏感信息**。服务方按自己的数据政策处理请求。

本版使用个人填写的密钥进行开发验证，没有供应商账号系统、额度管理或服务器。商业版共用密钥应放在受控后端，并增加身份验证、用量与成本管理。

## 本机加密的范围

通知的 **应用显示名、标题、正文、自动判断理由** 使用 Android Keystore 管理密钥的 AES-GCM 字段加密；API 密钥另行加密保存。加密失败不会降级为明文存储。应用关闭系统备份，日志不记录正文和密钥。

这不是全库加密：**包名、系统通知 key、通道、时间、内容 hash、分类标签、处理状态以及偏好配置等元数据仍以明文保存**。关注词、来源选择、服务地址与模型配置等偏好也不因正文加密而自动加密。应用处理或解锁显示时需要在进程内使用明文；设备凭据验证保护的是查看会话，不是每次后台读取的硬件认证。

Room v1 → v2 保留历史并新增自动结果及偏好；v2 → v3 增加字段加密版本，旧通知在启动时批量加密，之后执行数据库清理。无法承诺抹除旧系统备份、存储介质残留或此前已发送到云端的副本。清空历史只处理轻序当前本机数据。

## 界面与采集能力

- 选择来源后采集系统提供的文字通知；跳过自身、常驻通知与分组汇总，连接时同步仍有效的通知。
- 断线、进程启动及回到前台时可请求系统重绑；每轮最多三次，包含最小间隔与冷却，真实系统回调后才标记在线。界面区分正在恢复与已断开，支持手动重试。这不是常驻保活，无法保证绕过厂商后台限制。
- 单条通知解析失败不会中断其余通知；旧监听实例的迟到销毁回调不会把已连接的新实例标为离线。
- 优先读取安装应用的原图标，无法读取时使用聊天、日历或通用备用图标。
- 暖白／墨绿主题、系统深色模式，底部收件箱／已收起／设置导航。
- 使用小耳角色与浅深头像，支持启动过渡、页面切换、星标和列表展开动效；角色为静态 PNG 配合 Compose 动画。
- 原通知跳转入口仅存于进程内，失效时提示到来源应用查看。

## 并发与结果保护

入库与初分使用同一 Room 事务，重复快照保留原结果。后台结果仅在通知 key、内容版本、正文 hash 与待分析状态仍匹配，且没有人工纠正时落库。设置、授权或偏好变化会使旧分析结果失效；重新整理不覆盖当前内容的人工纠正。

新消息整理与云端失败重试使用独立工作队列，先完成一批本机处理，再进行少量云端请求，避免服务故障把新消息挂在网络退避队列后。失败次数按每条消息的处理状态保存，有限重试后停止自动请求，可手动重新整理。失败或锁屏暂停不会把已有本机结果改成待用户分类；锁屏限制开启时，解锁后的处理可继续云端复核。已提交请求不能因为之后关闭授权而从服务方撤回。

当前为单个 Gradle `:app` 模块，按职责分包。

## 构建与验证

使用 JDK 17、Android SDK Platform 35、Build Tools 34.0.0（AGP 默认），AGP 8.7.3／Kotlin 2.0.21／Gradle 8.9。在 Android Studio 打开目录并配置 SDK，或在 PowerShell 配置环境后执行：

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

APK 原输出为 `app/build/outputs/apk/debug/app-debug.apk`。存在 `.tools` 时可运行 `scripts/build-local.ps1`；脚本临时配置环境并在英文 TEMP 目录建立 Junction，规避 Windows 测试进程对中文路径的兼容问题。源码与输出仍在原工程。

测试覆盖规则与模型响应、入库初分、重复快照、数据库迁移及字段加密、迟到结果、人工优先、来源隐私限制、有限重试与重连、单条通知异常隔离、保留期、查看会话，以及 Compose 引导、服务切换和隐私设置交互。测试数量和通过状态以本次[验证记录](VERIFICATION-0.4.4.md)及最终 Gradle 报告为准，本文不沿用旧版本结论。

尚未连接 Android 真机或真实云服务进行完整联调。发布前需验证系统凭据流程与 120 秒过期、后台／熄屏锁回、系统截图限制、来源授权、厂商后台接收、真实中文通知判断、锁屏暂停与解锁恢复、配置变更时的请求竞态，以及覆盖升级和大字体界面。

## 当前限制

本版只整理轻序内部列表，**不新增系统提醒、响铃或定时摘要，不取消或静音原通知，没有端侧模型**。Android 通知监听通常在来源发布后收到事件，无法保证在原提醒响铃前拦截。

只能读取 Android 提供的通知内容，不能读取完整聊天记录或恢复系统隐藏的正文。后台限制和敏感通知保护因设备而异。同一个系统 key 仅保留最新正文，不拆分完整聊天消息，不保留旧正文历史。尚无导出、云同步、兴趣推荐流或自动摘要功能。
